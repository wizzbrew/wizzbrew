GOAL
Stop double writes from a double-clicked Confirm, add the per-user lock and kill switch keys,
and let anyone continue a public thread.

CONTEXT
Wizzbrew (a Discord bot) moved to a hybrid model on 2026-10-15 (plan.md "Interaction model").
`takePending` currently reads then deletes, so two quick Confirm presses can both run the
write. Pending actions and threads live in Upstash Redis.

CHANGES (match docs/contracts.md exactly)
1. Kv gains `take<T>(key)` (Upstash `redis.getdel`) and `setIfAbsent<T>(key, value, ttlSec)`
   (`redis.set(key, value, {nx: true, ex: ttlSec})`, true when the result is "OK"). FakeKv
   implements both against its clock.
2. keys gains `lock(discordUserId)` -> `wb:v1:lock:<id>`, `kill()` -> `wb:v1:kill`,
   `alert(event)` -> `wb:v1:alert:<event>` (event matches `^[a-z0-9_.-]{1,64}$`).
3. takePending: `kv().take(keys.pending(id))`. Missing or expired -> "expired". Another user ->
   put it back with `set(key, record, remaining TTL seconds, at least 1)` and return
   "not_yours". Otherwise return it. Two concurrent takes by the owner: exactly one gets the
   record (test with FakeKv: two calls, one PendingAction and one "expired").
4. loadThread(id, discordUserId, now): the owner, or anyone when the thread is public
   (`ephemeral === false`), gets the record (sliding TTL as now); a private thread and another
   user -> "not_yours". Callers decide whether to fork.
5. Tests for each change; existing assertions stay unless this card changes the behavior they
   check (the not-owner public thread case), and say which in DEVIATIONS.
