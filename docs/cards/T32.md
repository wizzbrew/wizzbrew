each other; beer-league built its context from the reply chain the same way.

BEHAVIOR
1. loadAskerFromMessage: discordUserId = author.id; discordName = nick ?? globalName ?? username;
   guildId; channelId; `linked` built exactly as loadAsker does (share the private helper rather
   than copy it; refactor within identity.ts only).
2. runMessagePipeline:
   - history from `m.chain`: a turn per entry, bot entries -> `{role: "assistant", text}`, others
     -> `{role: "user", text: "<authorName>: <content>"}`, each text `sanitizeForPrompt(text,
     600)`; keep the last 10.
   - question: `m.content`, sanitized; empty after the mention is removed -> the question
     "(the asker mentioned you without saying anything else)".
   - `runAskPipeline({requestId, asker, question, reply: {kind: "message", channelId,
     messageId}, history, now})`. Any error before the pipeline -> `deliverError(target,
     userMessageFor(err))`.
3. api/message.ts POST:
   - raw body via `request.text()`; headers `X-Relay-Timestamp`, `X-Relay-Signature`. Missing,
     a timestamp more than 300 s from now, or a signature mismatch (HMAC-SHA256 hex of
     `timestamp + "." + raw` with `config().relaySecret`, compared in constant time) -> 401.
   - Parse JSON and validate RelayMessage with zod (strict; chain at most 10) -> 400 on failure.
   - `isPaused()` -> 200 `{paused: true}` and nothing else (the relay stays quiet).
   - Otherwise `waitUntil(runMessagePipeline(m, crypto.randomUUID(), new Date()))` from
     "@vercel/functions" and return 202.
   - Never log message content beyond 200 characters (L24).
