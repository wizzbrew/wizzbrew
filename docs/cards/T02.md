BEHAVIOR
1. verify: `import { verifyKey } from "discord-interactions"`; in 4.4 it is
   `verifyKey(rawBody, signature, timestamp, publicKey): Promise<boolean>` (async). Return
   false, never throw, for empty or malformed inputs or a verifyKey rejection (log nothing).
2. api: base `https://discord.com/api/v10`. The real client reads
   `configFor("discordApplicationId", "discordBotToken")` (so the register script needs only
   Discord vars), lazily, once.
   - editOriginal: PATCH `/webhooks/{app_id}/{token}/messages/@original`, JSON body, no auth
     header.
   - followup: POST `/webhooks/{app_id}/{token}`, JSON body, no auth header.
   - registerCommands: PUT `/applications/{app_id}/commands`, or
     `/applications/{app_id}/guilds/{guild_id}/commands` when guildId is given, header
     `Authorization: Bot <token>`.
   - `Content-Type: application/json` on all three. Use global `fetch`.
   - 429: wait the body's `retry_after` seconds (or the `Retry-After` header) once if it is at
     most 5 s, then retry once; otherwise throw.
   - Other non-2xx: throw `DiscordError(status, message)` where message includes Discord's JSON
     `message` and `code` when present. For a 403 also name the permission: on
     registerCommands "the app needs the applications.commands scope in this server"; on
     webhook calls "the bot can't post here (check View Channel and Send Messages)". Never put
     the token in a message.
   - `setDiscordApiForTests(d)` swaps the singleton; null restores the real one.
3. commands: `COMMANDS` as RESTPostAPIChatInputApplicationCommandsJSONBody (`import type` from
   "discord-api-types/v10"; numeric literals for enum values). Every command: type 1,
   `integration_types: [0, 1]`, `contexts: [0, 1, 2]`, descriptions under 100 characters,
   plain words, no dashes. Options (type 3 = string):
   - ask: `question` required, max_length 500
   - schedule: `day` optional ("today, tomorrow, a weekday or a date"), `stage` optional,
     `tournament` optional
   - live: none
   - standings: `tournament` required
   - player: `name` required
   - link, unlink, me: none
4. scripts/register-commands.ts: top-level await;
   `discordApi().registerCommands(COMMANDS, configFor("discordDevGuildId").discordDevGuildId ?? undefined)`;
   prints how many commands went to which target ("guild <id>" or "global"). Never prints a
   token. Exit code 1 on failure with the error message.
