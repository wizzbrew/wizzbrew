CONTRACT (do not change; parseUserDate is new: add it)
```ts
export function nowBlock(now: Date): string;             // "Current time: Thu 2026-10-15 20:14 America/New_York"
export function parseWizzrobeTime(iso: string): Date;
export function discordTimestamp(d: Date, style?: "f" | "F" | "t" | "R"): string;
export function communityDate(d: Date): string;          // YYYY-MM-DD in community tz
export function parseUserDateTime(text: string, now: Date): { date: string; time: string; instant: Date };
                                                         // community clock; throws UserInputError (L3)
export function parseUserDate(text: string, now: Date): string;   // date words only -> YYYY-MM-DD; UserInputError
export function dayWindowUtc(date: string): { start: Date; end: Date };   // community day -> UTC bounds
```

BEHAVIOR
1. The zone is `config().communityTimezone` (import from "../config.js"). Use
   `Intl.DateTimeFormat` with that IANA zone for the specific instant (L4). No date libraries,
   never a hand-applied offset.
2. nowBlock: `Current time: <Ddd> <YYYY-MM-DD> <HH:MM> <zone>`, 24-hour, English weekday.
   nowBlock(2026-10-16T00:14:00Z) in America/New_York is exactly
   "Current time: Thu 2026-10-15 20:14 America/New_York".
3. parseWizzrobeTime: accepts ISO 8601 with `Z` or a numeric offset, optional fractional
   seconds. Anything else (no zone, garbage, invalid date) throws
   `WizzrobeError(502, "Wizzrobe sent an unreadable time")` (from "../errors.js").
4. discordTimestamp: `<t:${Math.floor(ms / 1000)}:${style ?? "f"}>`.
5. communityDate: the instant's calendar date in the community zone.
6. parseUserDate(text, now): trimmed, case-insensitive. Accepts exactly one of:
   - `today`, `tomorrow`;
   - a weekday name, full or 3-letter (`sat`, `saturday`): the next occurrence counting today
     as occurrence 0, so on a Saturday "saturday" is today;
   - `YYYY-MM-DD`;
   - `Oct 17`, `October 17`, `17 Oct`;
   - `10/17` (month/day).
   Month/day forms take the current community year, or next year if that date is before today.
   Invalid calendar dates (Feb 30) and anything else throw UserInputError with a short plain
   message naming what it couldn't read (no em dashes).
7. parseUserDateTime(text, now): an optional date part (as in 6, default today) and a required
   time part, in either order, separated by spaces or "at". Time forms:
   - `HHMM`, four digits 0000 to 2359: a 24-hour time, never a year (L3);
   - `H:MM` / `HH:MM` (24-hour);
   - `8pm`, `8 pm`, `8:30pm`, `8:30 pm`, `12am` = 00:00, `12pm` = 12:00;
   - a bare 1 or 2 digit hour 0 to 23 (`tomorrow 9` = 09:00).
   No time part, two time parts, or leftover words -> UserInputError. With a weekday and no
   explicit date, if the resulting instant is before `now`, move a week ahead (never in the
   past). Returns `date` (YYYY-MM-DD), `time` (HH:MM) and the UTC `instant` for that community
   wall time. A wall time inside the spring-forward gap -> UserInputError saying clocks change
   then; a repeated fall-back wall time -> the first (earlier) instant.
8. dayWindowUtc(date): start = instant of 00:00 community time on `date`; end = instant of
   00:00 on the next date (exclusive). DST days are 23 or 25 hours long. A malformed date throws
   UserInputError.
9. Rule L2: this file is the only place allowed to parse date strings or call toLocale*.

TESTS (tests/unit/time.test.ts; setup already sets COMMUNITY_TIMEZONE=America/New_York)
- nowBlock exact string above.
- discordTimestamp epochs for "f" default and "R".
- parseWizzrobeTime: "2026-10-16T17:00:00Z", "+00:00" offset, fractional seconds; "2026-10-16
  17:00" (no zone) throws WizzrobeError status 502.
- communityDate across UTC midnight (2026-10-16T02:00Z is 2026-10-15 in New York).
- L3 cases with now = 2026-10-15T16:00:00Z (Thu 12:00 local): "2300" -> 23:00 today, not year
  2300; "8pm" -> 20:00; "20:00"; "tomorrow 9" -> 2026-10-16 09:00; "sat 8:30 pm"; "2026-11-01"
  alone throws UserInputError; "8" alone -> 08:00 today; "Oct 17 2pm"; "10/17 1400";
  "noon tomorrow banana" throws.
- weekday never in the past: "thu 9am" at Thu 12:00 -> next week's Thursday.
- parseUserDate: today, tomorrow, "saturday" (Sat 2026-10-17), "2026-10-20", "Oct 20",
  "10/20", "Jan 5" -> 2027-01-05; "someday" throws.
- DST (L4): dayWindowUtc("2026-11-01") is 25 h, 04:00Z to 2026-11-02T05:00Z;
  dayWindowUtc("2026-03-08") is 23 h, 05:00Z to 2026-03-09T04:00Z; parseUserDateTime
  "2026-10-31 9am" -> 13:00Z and "2026-11-02 9am" -> 14:00Z; "2026-03-08 2:30am" throws
  (gap); "2026-11-01 1:30am" -> 05:30Z (first occurrence).
