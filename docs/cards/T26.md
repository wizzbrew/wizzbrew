GOAL

bracket pairings (verified live 2026-10-15). Free Challonge apps get 500 requests a month, so
the bot never calls Challonge per question: it keeps one snapshot per tournament and refreshes
it only when Wizzrobe's match list shows a completed match the snapshot hasn't seen. Never

CONTRACT (do not change)
```ts
export interface BracketSummary {
  tournament: string; bracketUrl: string; rulesUrl: string | null;
  state: string | null;                                   // derived, see 6
  alive: string[]; eliminated: string[];                  // participant display names
  recent: { round: string; players: [string, string]; winner: string | null }[];
  upcoming: { round: string; players: [string | null, string | null] }[];   // open or pending pairings; null = slot not decided yet
  source: "challonge" | "link_only";
  fetchedAt: string | null;                               // ISO time the snapshot was taken
}
export function bracketFor(tournamentId: number): Promise<BracketSummary>;
```

EXTERNAL FACTS
- Wizzrobe (through `callTool(await botAccessToken(), name, args)`; tenant is injected for you):
  `get_tournament {tournament_id}` -> `{id, name, bracket_url, rules_url, ...}`, where
  bracket_url looks like `https://speedgaming.challonge.com/sgl26alttpr` or is null.
  `list_matches {tournament_id: [id], limit: 500}` -> `{"result": [{id, status, ...}]}`;
  statuses include scheduled, checked_in, live, awaiting_result, complete, cancelled.
- Challonge API v2.1: base `https://api.challonge.com/v2.1`. Headers: `Accept:
  application/json`, `Content-Type: application/vnd.api+json`, `Authorization-Type: v1`,
  `Authorization: <CHALLONGE_API_KEY>`. A community (subdomain) tournament adds query
  `community_id=<subdomain>`; a plain `https://challonge.com/<url>` has no community_id.
  - `GET /tournaments/{url}/participants.json?page=N&per_page=100`: `{"data": [{"id": "1001",
    "type": "participant", "attributes": {"name", "seed", "final_rank", "states": {"active"}}}]}`
  - `GET /tournaments/{url}/matches.json?page=N&per_page=100`: `{"data": [{"id", "type":
    "match", "attributes": {"state": "pending" | "open" | "complete", "round": int,
    "identifier", "scores", "winner_id": int | null, ...}}]}`. Players are in
    `relationships.player1.data.id` and `player2`; the schema puts `relationships` inside
    `attributes`, JSON:API puts it beside them: accept either. Negative rounds are the losers
    bracket.
  - Pages: keep fetching while a page returns `per_page` items, at most 5 pages per list.
  - 429 means the monthly quota is used up.

BEHAVIOR
1. `t = await callTool(bot, "get_tournament", {tournament_id})`. `bracket_url` null or not a
   challonge.com URL -> `{source: "link_only", bracketUrl: "", ...empty lists, fetchedAt: null}`
   with the tournament name and rules_url.
2. Parse the URL: host `<sub>.challonge.com` -> community_id `sub`, `challonge.com` -> none;
   the first path segment is the tournament url.
3. Snapshot at `keys.cache("challonge", String(tournamentId))`: `{summary, completedIds:
   number[]}`, stored without TTL.
4. `completed` = ids of Wizzrobe matches with status "complete" from
   `list_matches {tournament_id: [tournamentId], limit: 500}` (that read is cached by mcp.ts).
5. Serve the snapshot as is when it exists, every completed id is in `snapshot.completedIds`,
   and it is under 6 hours old. Otherwise refresh, unless:
   - no `config().challongeApiKey` -> snapshot if any, else link_only;
   - the monthly guard: `kv().incrByFloat(keys.cache("challonge", "count-" + YYYY-MM), n,
     3456000)` counts every request made; read it first and if it is at or over 450, serve
     the snapshot or link_only and log warn "challonge.monthly_guard".
6. Refresh: fetch participants and matches; build the summary:
   - alive: participants with `states.active` true, by seed; eliminated: the rest, by
     final_rank then name;
   - recent: up to 8 complete matches, highest round first, round label "Round N" or
     "Losers round N", players by name, winner by `winner_id`;
   - upcoming: every open and pending match, lowest round first, a slot null when its player
     isn't set;
   - state: "complete" if every match is complete, "underway" if any is complete or open,
     else "pending";
   - `source: "challonge"`, `fetchedAt: new Date().toISOString()`.
   Save `{summary, completedIds: completed}`.
7. Any Challonge or parse failure during refresh: log warn "challonge.refresh_failed" with the
   status only, then serve the stale snapshot if there is one (its own fetchedAt), else
   link_only. Never throw into the answer.
