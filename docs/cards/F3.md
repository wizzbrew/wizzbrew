Change when the Challonge snapshot refreshes, to make as few API calls as possible: only when
someone asks, only when the snapshot is over 60 minutes old, never between midnight and 08:00

refreshes on a new completed match or after 6 h. Remove that.

CHANGES
1. Remove the `list_matches` call and `completedIds` entirely. The snapshot is `{summary,
   etags?: {participants?: string, matches?: string}}`.
2. Serve the snapshot without calling Challonge when any of these hold:
   - it is under 60 minutes old (from summary.fetchedAt; unreadable counts as old);
   - quiet hours: now is before today's 08:00 on the community clock. Compute
     `parseUserDateTime(communityDate(now) + " 08:00", now).instant` and compare instants
     (L2, L4: no hand-applied offsets). There is always a refresh window from 08:00 to midnight.
   With no snapshot at all, fetch even in quiet hours (once), so the first ask gets data.
3. Refresh sends `If-None-Match: <etag>` per list page 1 when an ETag is stored; a 304 for both
   lists keeps the summary but updates fetchedAt (the data is confirmed current). Store the new
   `ETag` response headers. Page 2 onward is fetched only when page 1 changed. Every request,
   304 included, counts toward the monthly guard.
4. Everything else stays: monthly guard at 450, failures serve the stale snapshot, no key and no
   snapshot gives link_only, Wizzrobe get_tournament still supplies bracket_url.
5. Tests: replace the completed-id tests with: under 60 min served without fetch; over 60 min
   refreshes; 02:00 Eastern with a snapshot -> no fetch; 02:00 with none -> fetch; 08:30 after an
   hour -> fetch; ETag sent and 304 keeps the summary with a new fetchedAt; list_matches is never
   called. Keep the other existing tests. FakeChallonge (tests/fakes/) has no ETag support: stub
   fetch inline for the ETag tests.
