EXTERNAL FACTS (live Wizzrobe MCP; call `callTool(await botAccessToken(), name, args)`, tenant
injected for you; reads are cached by mcp.ts)
- `list_stages {active_only: true}` -> `{"result": [{id, name, is_active, stream_url}]}`
- `get_schedule {date: "YYYY-MM-DD"}` (community clock) -> `{"result": [{"stage": "<name>",
  "matches": [{id, tournament, scheduled_at (UTC ISO), status, players: [names], stage,
  restream_url}]}]}`; statuses: scheduled, checked_in, live, awaiting_result, complete,
  cancelled, needs_reschedule.
- `list_tournaments {active_only: true}` -> `{"result": [{id, name, ...}]}`

BEHAVIOR
1. liveAnswer: stages, plus today's schedule (`communityDate(now)`), plus tomorrow's when fewer
   than 2 upcoming matches remain today. Per active stage, in stage order:
   - now: a match whose status is live, checked_in or awaiting_result, else none;
   - next: the first match with scheduled_at after now and status scheduled or checked_in.
   Text, one block per stage: `**<Stage>** <stream_url>` then `Now: <players joined " vs "> (<tournament>)`
   or `Now: nothing on`, then `Next: <players> (<tournament>) <t:EPOCH:t> (<t:EPOCH:R>)` or `Next:
   nothing scheduled`. `ephemeral: false`. Times via `parseWizzrobeTime` and
   `discordTimestamp` (L2, L5).
2. scheduleAnswer: day defaults to today. stage and tournament are resolved with
   `resolveByName` against list_stages and list_tournaments: none -> the text says it found no
   stage or tournament by that name and lists the names; ambiguous -> an Answer with `choices`
   (label = name, value = name) and text "Which one?". Then list that day's matches, filtered,
   grouped by stage: `<t:EPOCH:t> <players> (<tournament>)`, cancelled ones marked "(cancelled)".
   Nothing -> "Nothing is scheduled for <t:EPOCH_OF_DAY_START:D>." `ephemeral: false`.
3. No model call anywhere. Wizzrobe errors propagate (L16).
