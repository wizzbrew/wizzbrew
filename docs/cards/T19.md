GOAL
Implement the account capability (link, unlink) as one handler that /link, /unlink and plain
words ("connect me to SGL") all reach, and the page Wizzrobe redirects to after approval.

CONTEXT
Linking lets Wizzbrew act as the user in Wizzrobe. The link URL starts a login tied to the
asker's Discord account, so it must only ever be shown privately; the delivery step keeps
ephemeral answers private on every path. Tokens never appear in a message, page or URL shown.

BEHAVIOR: account.ts (every Answer has `ephemeral: true`)
1. link: `getLink(id)` exists -> "You're linked to Wizzrobe as <username>. Say unlink (or use
   /unlink) first to switch accounts." Otherwise `{url} = await startLink(id)` -> text "Link your
   Wizzrobe account so I can act for you: [Link Wizzrobe](<url>). The link works once and expires
   in 10 minutes."
2. unlink: no link -> "You're not linked." Otherwise `revoke(await open(rec.sealedRefreshToken))`
   (a failure logs warn "account.revoke_failed" with the status only and unlinking continues),
   `deleteLink(id)`, text "Unlinked. Ask me to link again any time."
3. Errors propagate (the pipeline turns them into replies).

BEHAVIOR: callback.ts
4. Query `code`, `state`, `error`. `error` -> 400 page "Linking was cancelled. You can close this
   tab." Missing code or state -> 400 "This link is incomplete. Ask Wizzbrew to link you again."
5. `await finishLink(code, state)` -> 200 "Linked. Go back to Discord; I can act for you now. You
   can close this tab." UserInputError -> 400 with its message. WizzrobeError -> 502 "Wizzrobe
   didn't accept the link (<detail>). Ask Wizzbrew to link you again." Anything else -> 500
   "Something went wrong. Ask Wizzbrew to link you again." and log error.
6. Minimal HTML (title "Wizzbrew", one paragraph, all text HTML-escaped); headers `Content-Type:
   text/html; charset=utf-8`, `Cache-Control: no-store`, `Referrer-Policy: no-referrer`. Never
   echo code, state or tokens.
