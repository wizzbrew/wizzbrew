GOAL
Build the small always-on process that lets people talk to Wizzbrew by @mention, DM, or reply:
it watches the Discord gateway and forwards those messages, with their reply chain, to Vercel.

CONTEXT
Wizzbrew's main app runs on Vercel and only receives slash commands and buttons over HTTP.
Vercel can't hold a gateway connection, so this relay does (on Railway, like beer-league). It
has no bot logic: Vercel answers by posting the reply itself. Contract: docs/contracts.md
"Relay" and the RelayMessage type in src/types.ts (copy the type; the relay can't import src/).

BEHAVIOR
1. Package: name "wizzbrew-relay", private, "type": "module", engines node ">=24". Exact pins:
   dependencies `discord.js` 14.27.0, `zod` 4.6.5; dev `typescript` 7.0.2, `vitest` 5.0.3,
   `@types/node` 26.6.3. Scripts: build `tsc`, start `node dist/index.js`, test `vitest run`.
   tsconfig: strict, NodeNext, outDir dist, include src. railway.json: build `npm ci && npm run
   build`, start `npm start`, restart policy always.
2. config.ts is the relay's only reader of process.env: RELAY_SECRET (32+ chars), DISCORD_BOT_TOKEN,
   WIZZBREW_URL (https), RELAY_CHANNEL_IDS (comma-separated ids; may be empty, DMs still work),
   validated with zod at start; errors name variables, never values.
3. forward.ts (pure, tested):
   - `shouldForward(m: {authorIsBot, isDm, mentionsBot, repliesToBot, channelId, parentId},
     allow: Set<string>)`: never bots; DMs always; otherwise (mentionsBot or repliesToBot) and
     (channelId or parentId) in allow.
   - `cleanContent(text, botId)`: remove `<@botId>` and `<@!botId>` and a leading `@Wizzbrew`
     left by discord.js cleanContent, trim.
   - `buildRelayMessage(...)` from plain fields to a RelayMessage (chain oldest first, at most 10).
   - `sign(secret, timestamp, body)`: hex HMAC-SHA256 of `timestamp + "." + body` (node:crypto).
4. index.ts: discord.js Client with intents Guilds, GuildMessages, MessageContent,
   DirectMessages and partial Channel. On messageCreate: compute the forward inputs
   (`message.mentions.users.has(botId)` only, never everyone or roles; replyToBot by fetching
   `message.reference.messageId` and comparing the author); if forwarded: `sendTyping()`, walk
   the reply chain (fetch each referenced message, up to 10, a missing one stops the walk), use
   discord.js `cleanContent` for text and member display names for authors, POST JSON to
   `<WIZZBREW_URL>/api/message` with headers `Content-Type: application/json`,
   `X-Relay-Timestamp`, `X-Relay-Signature`, 10 s timeout. A non-2xx or network failure: log, and
   reply once "I can't answer right now. Try again in a minute." with `allowedMentions: {parse:
   []}`. Log one line per forward (channel id, message id, status), never content. SIGTERM ->
   `client.destroy()` and exit.
5. README.md: what it does, env vars (names only), the Message Content intent requirement, and
   Railway setup in five steps.
