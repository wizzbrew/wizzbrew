EXTERNAL FACTS (Wizzrobe OpenAPI, 2026-10-15)
- Base `config().wizzrobeBaseUrl`; header `Authorization: Bearer <token>`; JSON bodies.
- Errors: JSON `{"detail": "..."}` on 400, 401, 403, 404, 429 (with a `Retry-After` header);
  422 is a validation error whose `detail` is an array of `{loc, msg, type}`.
- RescheduleRequestResponse (201): required `id` int, `match_id` int, `kind` string, `status`
  string, `reason` string, `requested_by_id` int, `created_at` string; nullable `proposed_at`,
  `original_scheduled_at`, `opponent_agreed_at`, `requested_by_name`, `decided_by_id`,
  `decided_by_name`, `decided_at`, `decision_note`.
- BracketMatchResponse (201 for booking; array items for my-open-matches): required `id`,
  `bracket_id`, `round`, `position` (ints), `state` ("pending" | "open" | "complete"),
  `created_at`, `updated_at`; plus nullable ints `group_number`, `entry1_id`, `entry2_id`,
  `winner_id`, `entry1_score`, `entry2_score`, `winner_to_id`, `winner_to_slot`, `loser_to_id`,
  `loser_to_slot`, `best_of`; `forfeit` bool; `status` string or null; `games` array.

BEHAVIOR
1. One private `request(token, method, path, body?)` helper using global `fetch`.
2. Map the body: proposedAt -> `proposed_at` (omit when undefined, and always omit for
   `kind: "cancel"`); scheduledDate -> `scheduled_date`, scheduledTime -> `scheduled_time`,
   comment -> `comment` (omit when undefined). `tournament_id` query only when given.
3. Validate responses with zod: the required fields above; allow unknown extra fields
   (`.passthrough()` or the zod 4 equivalent). A response that fails validation ->
   `WizzrobeError(502, "Wizzrobe sent an unexpected reply")`.
4. Non-2xx -> `WizzrobeError(status, detail, retryAfterSec)`, where detail is the string
   `detail`, or for 422 the `msg` values joined with "; " and status 400; no JSON -> the
   status text. Network failure -> `WizzrobeError(503, "could not reach Wizzrobe")`.
5. Never log or echo the token.
