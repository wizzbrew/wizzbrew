BEHAVIOR
1. `spec = SPECS[route]`, `r = ROUTES[route]`. Answer `ephemeral = r.ephemeral || ctx.ephemeral`.
2. Route `staff` returns at once, no model call: `{text: "Staff tools aren't in Wizzbrew yet.
   Use Wizzrobe directly.", ephemeral: true}`.
3. Routes with no read, client or write tools (help, chat) make one call with purpose "chat"
   and no tools; the answer is `textOf(msg)`.
4. Token for the connector: `r.auth === "public"` -> `botAccessToken()`; otherwise
   `userAccessToken(ctx.asker.discordUserId)` (NotLinkedError propagates).
5. System: two text blocks.
   - Block 1 (stable, cached): `voice(spec.register)`, a blank line, `SHARED_RULES`, a blank
     line, `spec.instructions`, with `cache_control: {type: "ephemeral"}`.
   - Block 2 (volatile, never cached): `nowBlock(ctx.now)`; `Community timezone: <tz>`;
     `Wizzrobe tenant: <slug> (pass it as tenant on every Wizzrobe tool call)`; the asker
     (`Asker: <discordName>, Discord id <id>`, then `Linked Wizzrobe account: <username>
     (user id <n>), roles: <list or none>` or `Not linked to Wizzrobe`); the router's params
     as `Params: <json>`. L1: the clock is only here.
6. Tools: `connectorParams(token, r.readTools).tools`, then `clientToolDefs(r.clientTools)`,
   then, for any route with read or client tools, `offer_choices`, and when `r.writeTools` is
   not empty, `propose_action`. Both strict, additionalProperties false:
   - `offer_choices`: "Ask the asker to pick when a name matches more than one thing. Ends the
     answer." Input `{prompt: string, choices: [{label: string, value: string}] (1..5)}`.
   - `propose_action`: "Propose one write for the asker to confirm. It does not run until they
     press Confirm. Ends the answer." Input `{tool: enum of r.writeTools, args_json: string
     (the tool's arguments as a JSON object, without tenant), summary: string (what they are
     confirming, plain words, times as <t:EPOCH:f>)}`.
   Pass `mcp_servers` and `betas` from connectorParams.
7. Messages: one user message, `sanitizeForPrompt(ctx.question)`. Loop at most 8 calls of
   `createMessage("responder", {max_tokens: 16000, system, tools, mcp_servers, betas,
   messages, output_config: {effort: "medium"}}, ctx)`:
   - append `{role: "assistant", content: msg.content}` exactly as returned (thinking blocks
     included, never edited: preserved thinking);
   - `pause_turn`: call again with nothing appended;
   - `tool_use` blocks (client tools only; MCP calls arrive as mcp_tool_use and are already
     answered): handle every block, then send all `tool_result`s in ONE user message;
     - a ClientTool -> `runClientTool(name, input, ctx)` as the result text;
     - `offer_choices` -> stop; Answer `{text: prompt, choices, ephemeral}`;
     - `propose_action` -> parse args_json and validate with `WRITE_ARGS[tool]`; failure ->
       a tool_result with `is_error: true` and the zod issue paths, keep looping; success ->
       stop; Answer `{text: summary, proposedAction: {tool, args, summary}, ephemeral}`;
     - an unknown tool name -> is_error tool_result "unknown tool";
   - `end_turn` (or `stop_sequence`): Answer `{text: textOf(msg), ephemeral}`;
   - an empty final text -> `ModelOutputError("empty", "the answer came back empty")`.
   Hitting 8 calls -> `ModelOutputError("iteration_cap", "the answer took too many steps")`.
8. Log info "responder.done" `{requestId, route, calls, tools: [names of mcp_tool_use and
   client tool_use blocks, in order]}`. Never log text or arguments (L24).
