the asker presses Confirm (L15). Read text blocks by type (L9); "me" is the asker (L7).

CONTRACT (do not change)

```ts
export function runResponder(route: Route, decision: RoutingDecision, ctx: AskContext): Promise<Answer>;
// AskContext { requestId, asker, question, now, ephemeral, history: ConversationTurn[] }

```

BEHAVIOR
1. Routes `live` and `account` never reach a responder: throw `Error("route <r> has no
   responder")`. Route `staff` returns at once: `{text: "Staff tools aren't in Wizzbrew yet. Use
   Wizzrobe directly.", ephemeral: true}`.
2. `spec = SPECS[route]`, `r = ROUTES[route]`; answer `ephemeral = r.ephemeral || ctx.ephemeral`.
3. System, two text blocks:
   - block 1 (stable, `cache_control: {type: "ephemeral"}`): `voice(spec.register)`, blank
     line, `SHARED_RULES`, blank line, `spec.instructions`;
   - block 2 (volatile): `nowBlock(ctx.now)`; `Community timezone: <tz>`; `Wizzrobe tenant:
     <slug> (pass it as tenant on every Wizzrobe tool call)`; `Asker: <discordName>, Discord id
     <id>`; then `Linked Wizzrobe account: <username> (user id <n>), roles: <list or none>` or `Not
     linked to Wizzrobe`; `Params: <json of decision.params>`. The clock is only here (L1).
4. The user message: when `ctx.history` is not empty, first a text part "Earlier in this
   conversation:" with one line per turn, `User: <text>` or `Wizzbrew: <text>`, each
   `sanitizeForPrompt(text, 600)`, then a blank line; then `sanitizeForPrompt(ctx.question)`. One
   user message, so the turn order is always valid.
5. Routes with no tools (help, chat): one `createMessage("chat", {max_tokens: 4000, system,
   messages, output_config: {effort: "low"}})`; answer `textOf(msg)`. For chat, block 2 also
   gets an event block: tournaments (name only) from `callTool(bot, "list_tournaments",
   {active_only: true})` and stages (name and stream URL) from `callTool(bot, "list_stages",
   {active_only: true})` with `bot = await botAccessToken()`; if either fails, log warn and leave
   it out.
6. Tool routes: token `r.auth === "public"` -> `botAccessToken()`, else
   `userAccessToken(ctx.asker.discordUserId)` (NotLinkedError propagates). Tools =
   `connectorParams(token, r.readTools).tools`, then `clientToolDefs(r.clientTools)`, then
   `offer_choices`, then `propose_action` when `r.writeTools` is not empty (both strict,
   additionalProperties false):
   - `offer_choices`: "Ask the asker to pick when a name matches more than one thing. Ends the
     answer." `{prompt: string, choices: [{label: string, value: string}] 1..5}`
   - `propose_action`: "Propose one write for the asker to confirm. Nothing runs until they
     press Confirm. Ends the answer." `{tool: enum r.writeTools, args_json: string (the tool's
     arguments as a JSON object, no tenant), summary: string (plain words, times as
     <t:EPOCH:f>)}`
   Pass `mcp_servers` and `betas` from connectorParams.
7. Loop, at most 8 calls of `createMessage("responder", {max_tokens: 16000, system, tools,
   mcp_servers, betas, messages, output_config: {effort: "medium"}}, ctx)`, and never past
   200 s from the start (check before each call; over -> `ModelOutputError("timeout", "that
   took too long")`):
   - append `{role: "assistant", content: msg.content}` unchanged (preserved thinking);
   - `pause_turn`: call again;
   - `tool_use` blocks (client tools; MCP calls come as mcp_tool_use, already answered): handle
     them all and send every tool_result in ONE user message. ClientTool -> `runClientTool(name,
     input, ctx)`. offer_choices -> stop with `{text: prompt, choices, ephemeral}`.
     propose_action -> parse args_json, validate `WRITE_ARGS[tool]`; failure -> `is_error`
     tool_result with the zod issue paths and loop on; success -> stop with `{text: summary,
     proposedAction: {tool, args, summary}, ephemeral}`. Unknown tool -> is_error "unknown tool".
   - `end_turn`/`stop_sequence` -> `{text: textOf(msg), ephemeral}`; empty text ->
     `ModelOutputError("empty", "the answer came back empty")`.
   - 8 calls -> `ModelOutputError("iteration_cap", "the answer took too many steps")`.
8. Log info "responder.done" `{requestId, route, calls, ms, tools: [mcp and client tool names in
   order]}`; never text or arguments (L24).
