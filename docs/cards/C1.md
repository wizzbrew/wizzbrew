CHANGES (match docs/contracts.md exactly)
1. types.ts: add `export interface ConversationTurn { role: "user" | "assistant"; text: string }`;
   `AskContext.history: ConversationTurn[]`; `ThreadRecord.turns: ConversationTurn[]` and the
   updated comments. Nothing else changes.
2. components.ts: new kind `{ kind: "followup"; threadId }` encoded `wb:followup:<threadId>`;
   round-trips; decode rejects a followup with a value part.
3. render.ts: `renderAnswer(a, {pendingId, threadId})`:
   - pendingId -> Confirm/Cancel row only (no follow-up button);
   - threadId with choices -> the choose row (as now);
   - threadId without choices and no pendingId -> one action row with a secondary button (style
     2) labeled "Ask a follow-up", custom_id from `{kind: "followup", threadId}`.
   Update the snapshots on purpose (the new button) and say so in DEVIATIONS.
4. pending.ts: thread TTL 1800 s (expiresAt now + 1800000) in saveThread and loadThread;
   `saveThread` stores `turns` capped to the last 6, each `text` cut to 1500 characters. Pending
   actions stay at 600 s.
5. router.ts: when `ctx.history` is not empty, the user message gets, after the "Asker linked"
   line and before the question, a block "Earlier in this conversation:" with each turn as
   `User: <text>` or `Wizzbrew: <text>`, each `sanitizeForPrompt(text, 500)`. The system block is
   unchanged and still cached.
6. Tests that build an AskContext or ThreadRecord get `history: []` or `turns: []`. Add tests: the
   followup custom_id round-trip; the follow-up button present without choices and pendingId and
   absent with either; pending thread TTL 1800 and turns capped at 6 and 1500 chars; the router
   user message includes earlier turns and the system block does not.
