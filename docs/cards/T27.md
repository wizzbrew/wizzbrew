BEHAVIOR: mine.ts
1. Exactly one `list_matches` call for the window (statuses cancelled and complete dropped).
2. Linked asker (`asker.linked`): keep matches whose `players` contains the linked
   `wizzrobeUsername`, compared case-insensitively. No get_match calls. opponents = the other
   names. `partial: false`.
3. Unlinked asker: for each listed match in time order, get its roster from
   `keys.cache("roster", String(matchId))` (`{players: [{name, discordId: string | number |
   null}]}`, TTL 21600); on a miss call `get_match` and store it. At most 20 uncached get_match
   calls per request; stop there with `partial: true`. Any numeric discord_id seen in a roster
   -> return "id_unreliable". Keep matches where a player's discordId is a string equal to
   `asker.discordUserId`; opponents = the other players' display names.
4. MyMatch: scheduledAt via `parseWizzrobeTime`; stage name; streamUrl = restream_url.

BEHAVIOR: clientTools.ts
5. clientToolDefs returns, for each requested name, a BetaTool with `strict: true` and
   `additionalProperties: false`:
   - `matches_for_me`: description "The asker's own upcoming matches in the next days.",
     input `{days_ahead: integer 1..14}` (required);
   - `challonge_bracket`: description "A tournament's bracket from Challonge: who is alive,
     eliminated, recent results and upcoming pairings, with the snapshot time.", input
     `{tournament_id: integer}` (required).
6. runClientTool validates input with zod (strict; extra keys rejected) and returns a JSON
   string:
   - matches_for_me: window = ctx.now to ctx.now + days_ahead days;
     `matchesForAsker(ctx.asker, window)`; "id_unreliable" -> `{"needs_link": true}`;
     otherwise `{"matches": [... with scheduled_at as ISO UTC], "partial": bool}`.
   - challonge_bracket: `bracketFor(tournament_id)` as JSON.
   - invalid input -> `{"error": "invalid input"}` (the model can retry); errors from Wizzrobe
     propagate (L16).
   - The asker comes only from ctx; input can't name another user.
